# Day 28 · 让两个推理副本服务一段 Agent 会话

毕业问题：对同一批有共享前缀、工具等待和突发请求的 Agent 会话，把请求优先送往可能持有前缀的副本，会怎样改变首 token 延迟、排队和 goodput？结论可以是改善、持平或退化。

**实验起点**　两张 H200 各跑一份相同模型。带上 Day 07 的请求格式、Day 10 的前缀样本、Day 12 的指标和 Day 19 的双副本轮询设置，使用 Day 27 选定的后端。

## 动手要求

1. 从有权使用的 Agent harness 或公开数据提取脱敏 trace，保留 session、请求到达、token 前缀、工具等待和依赖；回放器按同一时序向真实副本发请求。合成负载可用于调试，单列来源。
2. 实现能记录决策依据的前缀/会话感知路由，处理缓存信息未知和热点排队。与轮询都开启前缀缓存，保持同样卡数、模型 revision、token 输入、并发、冷/热起点和试验顺序控制；两种策略在本日条件下重跑。
3. 对齐每条请求、目标副本、排队、TTFT、TPOT 和失败，汇总 p95、样本数、缓存命中与满足 SLO 的 goodput/GPU。完成初步两策略对照后，研究验收须加入 least-loaded、session affinity、KV+load 以及关闭自身 Agent 状态信号的消融；按日志核验缓存驻留。
