# 每日课程模板与十五项验收

复制章节结构前先选定一个可检验的问题。例：第 4 天要说明一次带历史的两 token 前向是否与全序列重算一致。下列时间是备课参考，可按实际实验调整。

| 章节 | 教材和实验需要回答的问题 | 参考耗时 |
|---|---|---|
| Motivation | 谁遇到了什么瓶颈？指出可观察的症状 | 15 分钟 |
| Mental model | 画输入、状态、计算、输出；在图上走一个例子 | 30 分钟 |
| Theory | 写维度、单位、公式或复杂度，给适用条件与反例 | 60 分钟 |
| Guided walkthrough | 手算一个输入，映射到文件、函数与关键语句 | 45 分钟 |
| Hands-on lab | 指定前课产物、要亲手完成的函数、运行入口、独立对照 | 150 分钟 |
| Source code | 给固定版本、文件、符号和调用关系 | 60 分钟 |
| Benchmark | 先作定量预测，固定对照、冷/热、预热与重复，再解释分布 | 60 分钟 |
| Review | 交付证据、故障诊断、自测和挑战 | 30 分钟 |

### 作者和审查者逐项核对

1. 工程问题具体到可观察的现象。
2. 图示能帮助推演一个实际输入。
3. 给出公式、维度或复杂度，注明量纲。
4. 给出技术价值与适用边界。
5. starter 保留核心逻辑，学习者能从测试开始。
6. reference 可独立运行，用手算或官方实现校验。
7. 源码映射有固定版本和真实符号。
8. 环境锁与命令可以从干净 checkout 执行。
9. 公平基线只改变指定变量。
10. 原始结果带来源，缺失观测保留为空。
11. 前课代码、输入或记录可直接传到本课。
12. 给至少一个可据现象定位的失败。
13. 验收能被程序或原始证据证实。
14. 自测要靠推理或新输入回答。
15. 挑战有可验证的完成条件。

合并时标明通过的是教材静态检查、CPU 单测、数值对照、GPU 性能还是端到端验收，并保留未测项。
